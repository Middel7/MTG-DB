COMMANDES DE LANCEMENT — MTG-DB
================================================================================

MISE À JOUR COMPLÈTE (recommandé)
─────────────────────────────────
Enchaîne les 4 sources : Scryfall → Cardmarket → Game Changers → Tags Tagger.

    .\update.ps1

Options utiles :
    .\update.ps1 --dry-run              # affiche le plan sans rien exécuter
    .\update.ps1 --only cardmarket      # une seule source
    .\update.ps1 --skip tags            # tout sauf les tags Tagger (~7 min)
    .\update.ps1 --force                # réimporte le bulk Scryfall
    .\update.ps1 --tags-all             # retraite TOUS les tags (long)
    .\update.ps1 --stop-on-error        # arrête à la première erreur

Étapes disponibles pour --only / --skip :
    scryfall | cardmarket | game-changers | tags

Codes de sortie : 0 = succès | 1 = une étape a échoué | 2 = run déjà en cours
Journal du run  : logs\update_<horodatage>.log


MISE À JOUR AUTOMATIQUE (tâches planifiées Windows)
───────────────────────────────────────────────────
    .\scripts\install_scheduled_tasks.ps1          # installer
    .\scripts\install_scheduled_tasks.ps1 -Remove  # désinstaller

Crée deux tâches :
    MTG-DB Update   08:00 et 20:00 chaque jour   (--skip tags, ~7 min)
    MTG-DB Tags     dimanche 05:00                (--only tags, ~40 min)

    Get-ScheduledTask -TaskName 'MTG-DB*'              # vérifier
    Start-ScheduledTask -TaskName 'MTG-DB Update'      # lancer maintenant
    Get-ScheduledTaskInfo -TaskName 'MTG-DB Update'    # dernier résultat


PRODUCTION (Docker)
───────────────────
L'image declare un CMD et non un ENTRYPOINT : toute variante s'ecrit en
COMMANDE COMPLETE. « docker compose run --rm updater --skip tags » ne
fonctionne pas — Docker chercherait un binaire nomme « --skip ».

    docker compose run --rm updater                                          # le CMD : --skip tags
    docker compose run --rm updater python scripts/update_all.py --only tags
    docker compose run --rm updater python scripts/update_all.py --dry-run

En PRODUCTION, ce n'est plus docker-compose qui declenche les runs : deux Cron
Jobs Render construisent cette meme image (voir render.yaml).

Voir docs/deploiement.md pour l'ordonnancement, la supervision et les secrets.
